# محمّل الفيديو

أداة ويب لتحميل الفيديوهات، مبنية بحيث لا تكلّف تشغيلها شيئًا، ولا تَعِد بما
لا تستطيع تنفيذه.

المستودع: <https://github.com/mohamed-khairy-5i/VideoMaster>

---

## ما تفعله هذه الأداة فعلًا

أربع منصات. كل واحدة مُختبرة آليًا بتنزيل بايتات حقيقية والتحقق من توقيع الملف،
وليس بمجرد التأكد من أن الخادم ردّ بنجاح.

| المنصة | ما يعمل | الحدود المعروفة |
|---|---|---|
| YouTube | حتى 4K، دمج الصوت والصورة داخل المتصفح، استخراج الصوت | قد يفرض فحصًا آليًا على عناوين الاستضافة المشتركة |
| TikTok | نسخة بدون علامة مائية عند توفّرها | يرفض أحيانًا الطلبات القادمة من مراكز البيانات |
| Twitter / X | كل الجودات المرفقة بالمنشور | الحسابات المحمية والمنشورات المحذوفة |
| Reddit | دمج مسار الصورة مع مسار الصوت المنفصل | المجتمعات الخاصة، وقد يحجب ريديت عناوين الخوادم |

### منصات أُزيلت عن قصد

هذه ليست ميزات ناقصة، بل قرارات مقصودة موثّقة في الكود:

- **Vimeo**: لم يعد يوفّر أي ملف MP4 مباشر. مصفوفة `progressive` فارغة، وكل ما
  تبقّى مشفَّر: مسار DASH يحمل `ContentProtection` مع مفاتيح Widevine و
  PlayReady، ومسار HLS يحمل `EXT-X-KEY:METHOD=SAMPLE-AES` الخاص بـ FairPlay.
  فكّ هذا التشفير يتطلب الحصول على مفتاح محتوى، أي التحايل على وسيلة حماية
  تقنية، وهو ما يجرّمه قانون DMCA في المادة 1201. لا يوجد حلّ هندسي يجعل ذلك
  قانونيًا، لذلك أُزيلت المنصة بدل تركها زرًّا لا يعمل.
- **Instagram و Facebook**: يتطلبان جلسة مُصادَقة. لا يمكن دعمهما بصدق دون ذلك.
- **Dailymotion**: الرابط الذي كانت الأداة تبنيه لم يكن حقيقيًا أصلًا: كان
  يُركَّب نصيًا ولا يُطلب أبدًا، ويردّ بـ 403 دائمًا. وحتى مع رابط صحيح، ديلي
  موشن يوفّر HLS فقط، أي أن المستخدم كان سيحصل على ملف نصي بامتداد `.m3u8`
  بينما الواجهة تقول له «صوت وصورة، تحميل فوري».

## لماذا لا يكلّف التشغيل شيئًا

القاعدة المعمارية: **الخادم ينقل JSON فقط، والبايتات لا تمرّ عبر أي شيء نحاسَب
عليه بالحجم.**

```
المتصفح
   │  1. POST /api/extract          (دالة Netlify، JSON فقط، أقل من ثانية)
   │     تسأل المنصة عن البيانات وتُعيد روابط الجودات
   │
   │  2. GET /api/stream?u=…        (دالة حافّة Netlify، بثّ مباشر)
   │     تمرّر البايتات دون تخزين، وتدعم Range و 206
   │
   └─ 3. الدمج (عند الحاجة)         داخل المتصفح عبر ffmpeg.wasm
         نسخ مباشر `-c copy`، بلا إعادة ترميز وبلا فقدان جودة
```

ثلاث نتائج مباشرة:

1. **دالة الاستخراج لا تلمس الفيديو**، فلا تصطدم بحدّ زمن التنفيذ.
2. **الدمج يحدث على جهاز المستخدم**، فتزداد قدرة النظام كلما زاد المستخدمون بدل
   أن تنقص. هذا ما يسمح بجودة 4K مع صوت دون خادم معالجة.
3. **لا شيء يُخزَّن**، فلا توجد فاتورة تخزين ولا سجلّ لما حمّله أحد.

## التشغيل محليًا

```bash
npm install
npm run dev          # خادم التطوير
```

```bash
npm run build        # بناء الإنتاج (ينشئ sitemap تلقائيًا)
npm run preview      # معاينة ناتج البناء
npm run lint         # فحص الكود
npm run test:sw      # فحص ثوابت عامل الخدمة (بدون شبكة)
npm run test:mux     # اختبار محرّك الدمج في المتصفح (بدون شبكة)
npm run test:extract # اختبار المحرّك على الشبكة الحقيقية
npm run verify       # الأربعة معًا
```

### `npm run test:extract`

هذا الاختبار يصيب الشبكة عمدًا، لأن المحرّك يعتمد على واجهات طرف ثالث تتغير دون
إشعار.

الأهم: الاختبار **لا يكتفي بفحص شكل الكائن**. النسخة السابقة كانت تتحقق فقط من
وجود عنوان ومصفوفة جودات غير فارغة، ولهذا نجح رابط ديلي موشن الميّت طوال عمره.
الآن يُنفَّذ طلب فعلي بنطاق بايتات، وتُفحص البايتات الأولى للتأكد من أنها حاوية
فيديو حقيقية (`ftyp` أو توقيع WebM)، مع رفض صفحات الخطأ بصيغة HTML وقوائم
التشغيل النصية والأجسام الفارغة.

قد تظهر نتيجة «skipped» ليوتيوب: هذا فحص آلي مرتبط بعنوان IP المشترك، وليس خطأ
برمجيًا.

### `npm run test:sw`

عامل الخدمة يفشل بطرق لا تظهر في التطوير العادي: يعمل للزائر العائد ويفشل للزائر
الجديد، أو يفشل بدون اتصال فقط، ويبقى في متصفح المستخدم حتى يتغيّر مفتاح التخزين.
هذا الفحص يثبّت الثوابت التي كُشفت بالقياس في متصفح حقيقي، وأهمها خطآن:

1. **تخزين وسيط البثّ.** كان `/api/` يُخزَّن، فتُنسخ كل بايتات الفيديو إلى ذاكرة
   المتصفح أثناء التحميل حتى تُستنفد الحصة وتبدأ التحميلات بالفشل.
2. **صفحة فارغة بدون اتصال في أول زيارة.** فيت يضيف `crossorigin` إلى وحدات
   جافاسكربت، فيطلبها المتصفح بوضع CORS، بينما `cache.add()` يخزّنها كاستجابة
   `basic`. لذلك كان `cache.match(request)` يفشل في المطابقة: الملف موجود في
   الذاكرة ويظهر في أدوات المطوّر، والطلب مع ذلك يخرج إلى الشبكة ويموت بدون
   اتصال. النتيجة كانت `HTTP 200` بجسم فارغ تمامًا. ملف CSS وحده كان ينجح لأنه
   بلا `crossorigin`، وهذا ما كشف النمط. الحل: المفاتيح على المسار لا على كائن
   الطلب، وهو آمن لأن أسماء هذه الملفات تحمل بصمة المحتوى.

الفحص ثابت (بلا متصفح وبلا اعتماديات) ليعمل في أي مكان بتكلفة صفر. للتحقق
السلوكي الكامل: ابنِ المشروع، شغّل `npm run preview`، افتح الصفحة **مرة واحدة**،
ثم اقطع الشبكة من أدوات المطوّر وتنقّل. يجب أن تُعرض الصفحة لا أن تظهر بيضاء. لا
تُحدّث الصفحة قبل قطع الاتصال، لأن التحديث كان هو ما يخفي الخطأ الثاني.

### `npm run test:mux`

الدمج في المتصفح هو الميزة التي تميّز المشروع فعلًا: بدونها يحصل المستخدم على
فيديو 4K صامت. ومع ذلك لم يكن عليها أي اختبار، وهكذا نجا فيها عطبان في إدارة
الموارد.

الاختبار يستورد `src/utils/muxer.js` **نفسه**، ويعيد توجيه استيرادَي الـCDN داخله
إلى بدائل محلية عبر خطّافات محمّل Node. لا شبكة، ولا تنزيل 30 ميجابايت من
`wasm`، ولا إعادة كتابة للكود المفحوص: اختبار يعيد بناء موضوعه لا يثبت شيئًا.
بدائل الاختبار في `scripts/fixtures/` تنسخ دلالات المكتبة الحقيقية حرفيًا
(`on` يُلحق بمصفوفة دون فحص التكرار، و`off` يحذف بالهوية).

العطبان اللذان يمنعهما:

1. **تراكم مستمعي التقدّم.** نسخة `ffmpeg` تُخزَّن وتُعاد للاستخدام طوال الجلسة،
   وكان كل دمج يسجّل مستمعًا مجهولًا لا يُزال أبدًا. القياس على عشر عمليات دمج:
   **590** نداء تقدّم بدلًا من **140**، أي أن الدمج العاشر يشغّل عشرة مستمعين في
   كل نبضة، تسعة منها تخص تحميلات انتهت.
2. **عدم تحرير الذاكرة عند الفشل.** حلقة تنظيف نظام الملفات الوهمي كانت تقع بعد
   مسار النجاح، فإذا فشل `exec` بقي مسار الفيديو ومسار الصوت في ذاكرة `wasm` حتى
   نهاية الجلسة. محاولتا 4K فاشلتان تكفيان لحجز عدة جيجابايت، فتفشل بعدها كل
   عملية دمج لسبب لا علاقة له بالملف الذي اختاره المستخدم.

الحل الواحد للعطبين: مستمع بمُعرِّف مُسمّى، و`finally` يُزيله ويُفرّغ الملفات في
كل الحالات. وقد تحقّقنا من أن الاختبار يرصد فعلًا: بإرجاع الكود إلى نسخته السابقة
يسقط **7** فحوص من **25** مع أرقام صريحة (`14, 24, 34, 44, 54`)، لا مجرّد نجاح
صامت.

## البنية

```
netlify/
  functions/
    extract.js            نقطة النهاية: تحقّق من المدخل، توجيه، تغليف الروابط
    lib/
      detect.js           تطبيع الروابط + حماية SSRF + قائمة المضيفين المسموحين
      youtube.js          مستخرج يوتيوب (InnerTube) مع مصادر بديلة
      platforms.js        بقية المستخرجات، مع توثيق أسباب الإزالة
      fallback.js         مرايا Piped / Invidious
  edge-functions/
    stream.js             وسيط البثّ: Range، Content-Disposition، قائمة مضيفين
src/
  components/             Header, Footer, VideoDownloader
  pages/                  Home, About, Platform, Privacy, Terms, NotFound
  utils/
    api.js                طبقة الواجهة + SUPPORTED (مصدر الحقيقة للمنصات)
    muxer.js              الدمج داخل المتصفح عبر ffmpeg.wasm
  styles/index.css        الرموز التصميمية (فاتح/داكن في مجموعة واحدة)
scripts/
  verify-engine.mjs       اختبار المحرّك الذي يفحص البايتات
  generate-sitemap.mjs    توليد sitemap وقت البناء من SUPPORTED
.agent/skills/            قواعد التصميم المُطبَّقة على هذا المستودع
```

### مصدر الحقيقة الواحد

`SUPPORTED` في `src/utils/api.js` هي القائمة التي تُشتقّ منها كل واجهة تعرض
المنصات: الصفحة الرئيسية، التذييل، صفحة «من نحن»، صفحات المنصات، وملف
`sitemap.xml`. لا يوجد عدد مكتوب يدويًا في أي مكان، لأن العدد المكتوب يدويًا هو
بالضبط ما يتحوّل إلى كذبة صامتة عند أول تغيير.

## الأمان

- **حماية SSRF**: تُرفض `localhost` والعناوين الرقمية المباشرة والنطاقات
  الداخلية و `169.254.*` (نقطة بيانات السحابة الوصفية).
- **قائمة مضيفين مغلقة للوسيط**: وسيط البثّ لا ينقل بايتات إلا من نطاقات محدّدة
  مسبقًا، وإلا لتحوّل إلى وسيط مفتوح يستخدمه أي شخص.
- **منع حقن الترويسات**: تُزال محارف التحكّم من اسم الملف قبل وضعه في
  `Content-Disposition`.
- **الروابط الأصلية لا تصل للمتصفح**: تُستبدل بروابط عبر الوسيط، لأن شبكات
  التوزيع لا ترسل ترويسة CORS، ولأن الرابط المباشر يفتح تبويبًا بدل أن يحفظ ملفًا.

## الخصوصية

لا حسابات، ولا تتبّع، ولا سجلّ لما يُحمَّل. عامل الخدمة (`sw.js`) يتجاهل
`/api/` صراحةً، لأن نسخ فيديو بحجم غيغابايتات إلى ذاكرة التخزين المؤقت للمتصفح
يستنفد الحصة ويكسر التحميلات اللاحقة.
